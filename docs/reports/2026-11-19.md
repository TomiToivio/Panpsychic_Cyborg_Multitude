**A decision record is sufficient only if a later reader can re-derive and challenge the status, and no schema check decides that [preprint, schema analysis on 164 seeded defect variants plus a coding audit of real statements; Amadeus Brandes, "Record Sufficiency: What a Decision Record Must Preserve When an Unsettled Claim Becomes an Operative Status", [arXiv:2611.23422](https://arxiv.org/abs/2611.23422), submitted 17 November 2026; not previously reported here].** Organisations keep evidence, logs and approvals but often not the step by which an unsettled claim became an operative status — an accepted label, a released image — so a later reader cannot tell what the status was allowed to mean. Sufficiency is defined by four uses — **explain, bound, re-derive, challenge** — decomposed into ten questions, four mechanical checks, and a separation that matters: *conformance*, which the checks decide; *adequacy*, whether the answers are specific enough to use, which needs a reader; *fidelity*, which no check on the record decides; and merits, which sufficiency does not require. On 164 single-defect variants of three synthetic records, schema validation rejects every variant with a deleted required property and **none of the others**, and accepts a record whose claim, rule, scope, limits and challenge route are all empty. The authors state the consequence without softening it: **a false record passes every check.** Applied to the EU Digital Services Act's statement-of-reasons schema, four of the ten questions are answered in full, two in part and four not at all — why the matter was unsettled, what the status depends on, whether it can be re-derived, and how to challenge it. ### 4. News, technology and events [established vendor engineering; one guidance document; nothing enacted]

**The runtime control plane arrived, built on an open contract, and the versioned receipt is the part worth taking [established vendor announcement, primary source; Mehrnoosh Sameki, Mohamed Elmergawi, Mike Shi, Liam Crumm and Microsoft's Responsible AI team, "Introducing agent controls: An enterprise control plane for agent behavior", 18 November 2026, [commandline.microsoft.com](https://commandline.microsoft.com/introducing-agent-controls-an-enterprise-control-plane-for-agent-behavior/); shipped service and announced intent, not an independent audit].** A managed Azure service centrally defines, manages and evaluates policies governing agent behaviour across frameworks, platforms and clouds, built on two primitives Microsoft has open-sourced. **Agent Hooks** defines *where* control happens: a common set of intervention points across the agent lifecycle — startup, input, model calls, tool calls, output, shutdown — where the runtime pauses and asks for a decision. **The Agent Control Specification (ACS)** defines *how* the decision is made: an open request-and-decision contract that gathers evidence through annotators (safety classifiers, LLM judges, deterministic business rules, any external API) and passes it to a policy engine such as Rego. Verdicts are **allow, deny or transform**, and every evaluation returns a **receipt that identifies the policies and versions applied**, recorded alongside the execution outcome so a team can trace each action back to a policy decision. The stated motive for opening the primitives is portability — a policy written once should hold wherever an agent runs, and "a policy that lives in a system prompt is a suggestion".

PCM reading: this is the gate-not-a-promise distinction that the 14 November reversibility preprint formalized, shipped as an intervention point with a versioned receipt attached — and the receipt is the detail worth stealing, because a decision that names the rule and the rule's version can be argued with, while one that names only an outcome cannot. Two limits stay named. The gate is operated by the vendor and the receipt is issued by the enforcing party, which is the auditor-independence problem moved somewhere new rather than solved. And the open contract is the only part a node can carry away when it leaves — so the leaving-node test is now concrete and cheap: can a non-Azure runtime consume an ACS policy and produce a receipt today?
